# ESP32-P4 FOC —— 2208 无刷电机驱动与调试工具集

基于 **ESP32-P4** 的磁场定向控制（FOC）实现，面向 **灯哥 FOC 2208** 云台电机，
配套 AS5600 磁编码器、INA199 双电阻相电流采样。仓库里同时包含调试过程中用到的
各个独立测试程序（LED / WS2812 / EC11 编码器 / USB-Serial-JTAG）。

所有代码均在实机上验证通过：**8.6 → 171 rpm 全速段速度误差 ≤0.5 rpm，Id 收敛到 0 附近**。

## 硬件

| 项目 | 规格 |
| --- | --- |
| 主控 | ESP32-P4（本次实测 rev v3.2，双核 400MHz） |
| 电机 | 灯哥 FOC 2208 云台电机，12N14P，**7 极对**，110KV，额定 12V/2A |
| 角度反馈 | AS5600 磁编码器（I2C，0x36，12bit） |
| 电流采样 | 双电阻 inline 相电流，INA199A1（增益 50V/V） |
| 分流电阻 | **R015 = 0.015Ω**（早期版本用 R500 = 0.5Ω，见下方说明） |
| 驱动板 | 双路三相驱动（M1 / M2 两个通道） |

### 电流采样链路换算

```text
灵敏度 = R_shunt × Gain = 0.015Ω × 50 = 0.75 V/A = 0.75 mV/mA
零点   = VREF = 1.65V（双极性，可测正负电流）
量程   = (3.1 - 1.65) / 0.75 ≈ ±1.93 A
```

> **为什么换掉了 0.5Ω 分流电阻**：0.5Ω × 50 = 25mV/mA，满量程只有 **±124mA**，
> 对电机驱动来说远远不够，而且 1A 时压降 0.5V、耗散 0.5W。
> 换成 15mΩ 后量程扩大到 ±1.93A。
> 同时 INA199 的 REF 必须从 GND 抬到 **1.65V**，否则只能测单向电流，负半周会被削平。

## 快速开始

```bash
# 环境：ESP-IDF v6.x
. $IDF_PATH/export.sh

cd firmware/foc
idf.py set-target esp32p4      # 配置已写在 sdkconfig.defaults
idf.py build
idf.py -p /dev/ttyACM0 flash
```

串口控制台（115200，走 CH343 UART）：

| 命令 | 说明 |
| --- | --- |
| `run` / `stop` | 启动 / 停止 |
| `f <Hz>` | 目标电频率（电频率 ÷ 极对数 × 60 = 机械 rpm） |
| `i <mA>` | 电流限幅（仅电流环模式有效） |
| `dump <n>` | 采样导流，每 10ms 打印一次三相电流 |
| `st` | 打印状态 |
| `cal` | 重新标定电角度零点与方向 |
| `ol` | 开环 V/f 测试（不依赖编码器与标定） |

辅助脚本：

```bash
python tools/boot.py          # 复位并抓取启动日志
python tools/spd.py 5 800 12  # 以 5Hz、800mA 限幅运行 12 秒
python tools/sweep.py 2,3,5,8,12,16,20 800 5   # 扫速测试
python tools/dump.py 3 60     # 运行中采样 60 点三相电流
```

### 两种运行模式

`firmware/foc/main/main.c` 顶部有开关：

```c
#define USE_CURRENT_LOOP   1   // 1 = 速度→电流 级联 FOC；0 = 电压模式速度环
```

电压模式（`0`）不依赖电流采样，只靠编码器闭环换相，适合电流采样硬件异常时排障。

## 上电自动标定

`calibrate_electrical_angle()` 会给两个不同电角度（0° 与 90°）施加吸引磁场，
读编码器位移，从而得到：

- **编码器方向** `s_enc_dir`（±1）
- **电角度零点** `s_enc_off`
- **顺带校验极对数**（2208 应为 7，实测通常在 6.5~7.0）

> 极对数**不再**由测量值自动覆盖，而是固定用 datasheet 的 7。
> 早期版本用单步 90° 位移反推极对数，实测结果在 7.59 / 9.23 / 9.57 之间乱跳，不可靠。

## 调试踩坑记录

这些问题每一个都真实耗掉过时间，记录下来供参考。

### 1. 三处符号必须自洽

```c
// ① 电角度
θ_e = wrap2π( s_enc_dir × pole_pairs × θ_mech + θ_off );

// ② 转矩方向（跟随编码器方向，不能写死）
iq_ref *= TORQUE_SIGN * s_enc_dir;

// ③ 电流采样极性（实测 +Vq 却得到 -Iq 时说明整体反了）
iu = SENSE_SIGN * (mv_u - offset_u) / sens;
```

②③ 任意一个反了，表现都是"电机不转或速度环正反馈飞车"。

### 2. 时序与采样类

- **相位不能用"固定步数 × 假设每步 N ms"推进**：`CONFIG_FREERTOS_HZ=100` 时
  `pdMS_TO_TICKS(2)` 会被截断成 0，延时失效，实际频率跑到目标的 50 倍。
  必须用 `esp_timer_get_time()` 实测 dt 积分。
- **周期性信号不能用瞬时值打日志**：报告周期 1.000s 与电频率整数倍重合时，
  每次采样落在波形同一相位，读数会被系统性带偏。必须统计窗口均值/极值。
- **编码器读数要放在慢操作之后**：先做 ADC 采样、再读编码器，并对电角度做
  `θ_e += ω_e·dt` 前向补偿，否则高速时角度过期会导致 dq 分解失效。

### 3. 硬件类（最耗时间，而且伪装成软件问题）

| 现象 | 真实原因 |
| --- | --- |
| 某相电流读数恒定顶到 ADC 满量程 | INA199 虚焊，输出悬空 |
| 同一转速所需调制比突然涨 9~13 倍 | 电池电量不足 / 相线松动 |
| I2C 时通时不通，`ESP_ERR_TIMEOUT` 与 `NOT_FOUND` 交替 | 端子接触不良（连锡/虚接） |
| 5Hz 能跑但更高就跑不动、电流暴涨 | 三根相线中有一根松动 |

**判断技巧**：`ESP_ERR_NOT_FOUND` 表示总线正常但地址无应答；
`ESP_ERR_TIMEOUT` 是非预期失败，通常意味着总线本身没工作起来（上拉/被拉低）。
